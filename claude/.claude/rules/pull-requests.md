# Pull requests

- Keep refactors and behavior changes in separate changes. When a task needs both, say so
  before writing code and propose this order: tests for the existing behavior, the refactor
  with those tests held constant, then the behavior change. Drive-by cleanup gets its own
  change or gets left alone.
- Before pushing commits to or merging a PR someone else authored, ask me whether the
  author has agreed.
- Load the `pr-description` skill before writing or editing a PR body.
